# 도쿄 여행 플래너

숙소와 꼭 가고 싶은 메인 스팟만 넣으면 **이동 동선 → 가볼만한 곳 → 주변 맛집·카페** 순서로 일정을 채워 주는 모바일 우선 웹앱입니다.
기본값은 4박 5일, 4명이며 설정에서 바꿀 수 있습니다.

**바로 쓰기(휴대폰·PC):** https://contentsfit0914.github.io/Travelplan/

- 장소 검색·추천·평점·사진·영업시간: Google **Places API (New)**
- 이동 경로·소요시간·대중교통 노선: Google **Routes API**
- 지도: Google **Maps JavaScript API** (키가 없으면 데모 모드로 OpenStreetMap 지도 사용)

## 사용 흐름

| 단계 | 화면 | 하는 일 |
| --- | --- | --- |
| 1 | 항공편·기본 정보 | 도착 날짜·시간·공항, 출발 날짜·시간·공항(하네다/나리타), 입국 수속 여유, 이륙 전 공항 도착 여유, 인원, 이동수단, 도보 거리, 페이스. 날짜는 항공편에서 계산 |
| 2 | 숙소 | 호텔 검색·선택, 체크인·체크아웃 시간, 첫날 숙소 도착 후 쉬는 시간 |
| 3 | 메인 스팟 | 꼭 갈 곳을 검색하거나 인기 스팟 칩으로 추가하고, 장소별 체류시간을 조정합니다 |
| 4 | 시간·식사 | 일정 시작·마무리, 아침(건너뛰기 가능)·점심·저녁 시각, 식사 소요시간, 식사시간 오차범위(10분/30분/1시간/2시간) |
| ✨ | 자동 일정 | 가까운 스팟끼리 묶어 날짜별로 나누고(도착일·귀국일은 적게), 날짜마다 동선을 최적화합니다 |

일정 화면에서는 날짜별로 다음 3단계를 따라 채웁니다.

1. **이동 동선**: 지도와 타임라인에 숙소 → 스팟 → 숙소 경로, 구간별 이동수단·시간, 도착·출발 시각이 표시됩니다.
2. **가볼만한 곳**: 동선 전체나 특정 장소 주변의 관광지를 평점과 '동선에서 벗어나는 시간' 기준으로 추천합니다. 비어 있는 시간대 카드를 누르면 그 근처를 추천합니다.
3. **맛집·카페**: 점심·저녁 시간대에 식당이 없으면 그 위치에 `식당이 비어 있어요` 카드가 생기고, 누르면 그 시간에 있을 장소 주변 맛집을 추천합니다. 라멘·스시 등 키워드 필터를 쓸 수 있습니다.

추천 목록에서 `＋ 추가`를 누르면 지도에 번호가 붙은 스팟이 생기고, 추가 이동시간이 가장 적은 자리에 들어가며 경로가 다시 그려집니다.
맛집은 비어 있는 식사 자리로, 카페는 오후(15시 전후) 쉬는 자리로 우선 배치됩니다.

### 시간 계산 규칙

- 첫날: 착륙(+입국 수속 여유) → 공항→숙소 이동 → '숙소 도착·짐 풀기'(쉬는 시간, 체크인 전이면 짐 맡기기) → 일정 시작
- 마지막 날: 이륙 시각 − 공항 도착 여유 − 숙소→공항 이동 = 숙소에서 늦어도 출발해야 하는 시각. 일정이 그보다 늦게 끝나면 경고
- 식사 자리: 목표 시각에 가장 가까운 빈 틈(이전 장소를 떠나는 시각)을 고릅니다. 예) 11:00 도착·숙소까지 1시간·휴식 30분이면 12:30(30분 늦음)이 11:00(60분 빠름)보다 가까우므로 12:30 숙소 근처. 그날 마지막 일정 뒤라면 목표 시각까지 기다렸다 먹습니다
- 맛집 범위: 오차범위 끝(목표+오차)까지 남은 시간만큼 이동할 수 있는 곳까지 찾습니다(최소 10분·최대 60분). 예) 점심 12:00·오차 1시간·12:30 자리 → 30분 이내. 오차 10분이면 이미 늦었으므로 가장 가까운 곳(도보 10분 이내)

- 도착 시각 = 이전 장소 출발 + 이동시간, 출발 시각 = 도착 + 체류시간
- 이동수단 `자동`: 도보 허용 거리(기본 1km) 이내는 도보, 그 밖은 기본 이동수단. 구간의 이동수단 버튼을 누르면 자동 → 도보 → 대중교통 → 택시로 바뀝니다.
- 숙소 복귀가 목표 시각을 넘으면 요약 막대가 빨갛게 표시되고 초과 시간을 알려 줍니다.
- Google 영업시간이 있으면 '도착 시각에 영업 중이 아닐 수 있어요', '머무는 중에 영업이 끝나요'를 경고합니다(요일 반영).
- 기본 체류시간은 제안값입니다: 박물관·미술관 120분, 공원 75분, 신사·절 50분, 전망대 75분, 쇼핑몰 90분, 그 외 관광 60분, 식사 75분, 카페 45분. 여행 페이스(여유롭게 ×1.25, 알차게 ×0.8)가 관광지에 반영됩니다.

### 기타 기능

- 식당·카페 상세: 추천 목록에서 식당·카페를 한 번 누르면 지도에서 위치를 보여 주고, 한 번 더 누르면 상세 팝업이 열립니다. 사진, Google AI 리뷰 요약(Gemini), 가격대·제공 항목, 최근 리뷰, 주소·전화·영업시간을 보여 줍니다. ✕·닫기·바깥 영역·Esc로 닫습니다.
  - AI 리뷰 요약은 Google이 제공하는 경우에만 나옵니다. 일본 장소는 일본어·영어 요약만 제공되는 경우가 많아, 한국어 요약이 없으면 일본어 원문을 보여 줍니다.
  - 메뉴판(메뉴 항목) 데이터는 Google Places API에서 제공되지 않아 Google 지도·공식 웹사이트 링크로 연결합니다.
  - 상세 정보는 팝업을 열 때만 요청하고 세션 동안 캐시합니다. 리뷰·AI 요약 필드는 상위 과금 등급(SKU)이므로 사용량을 확인하세요.

- `⇅ 동선 최적화`: 최근접 이웃과 2-opt로 이동시간을 줄이고, 식사·카페는 목표 시각 근처에 다시 넣습니다. 결과는 `되돌리기`로 취소할 수 있습니다.
- 구간별 `길찾기 ↗`, 하루 전체 `Google 지도로 보기`: 휴대폰의 Google 지도 앱으로 바로 열립니다.
- 공유: 텍스트 일정 공유(휴대폰 공유 시트), JSON 파일 내보내기·불러오기로 일행과 같은 일정을 나눠 씁니다.
- 데이터는 브라우저(localStorage)에만 저장됩니다. 서버가 없습니다.

## 내 PC에서 실행하기

필요한 것은 **Node.js** 하나입니다. 다른 설치나 명령어는 필요 없습니다.

1. **Node.js 설치**(처음 한 번): https://nodejs.org 에서 **LTS** 버전을 받아 기본 설정으로 설치합니다.
2. **앱 내려받기**: GitHub 저장소에서 `claude/tokyo-travel-planner` 브랜치를 고르고 **Code → Download ZIP**을 누른 뒤 압축을 풉니다.
3. **실행**
   - 윈도우: `start-windows.bat` 더블클릭
   - 맥: `start-mac.command`를 **우클릭 → 열기** (처음 한 번은 '확인되지 않은 개발자' 경고가 나오면 '열기')
4. 브라우저에 `http://localhost:5173`이 자동으로 열립니다. 검은 실행 창을 닫으면 앱이 종료됩니다.
5. 앱의 ⚙ 설정에서 Google API 키를 넣습니다. 키의 웹사이트 제한에 `http://localhost:5173/*`가 있어야 합니다.

- 실행 서버는 이 PC에서만 접속되도록 열립니다(같은 와이파이의 다른 기기에서는 접속 불가). 앱 파일 외의 파일은 열리지 않습니다.
- 일정과 키는 사용한 브라우저에 저장됩니다. 크롬에서 만든 일정은 크롬에서 열어야 보입니다.
- `5173번 포트를 이미 다른 프로그램이 쓰고 있어요`가 뜨면 이미 열린 실행 창을 닫고 다시 실행하세요.

개발자용: `npm start`(= `node server.mjs`), `npm test`.

## Google Maps Platform 설정

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 프로젝트를 만들고 결제 계정을 연결합니다.
2. **API 및 서비스 → 라이브러리**에서 다음 3개를 사용 설정합니다.
   - Maps JavaScript API
   - Places API (New)
   - Routes API
3. **사용자 인증 정보 → API 키 만들기** 후 반드시 제한을 겁니다. (아래 '보안' 참고)
4. 키 넣는 방법(둘 중 하나)
   - 개인 사용: 앱 ⚙ 설정 → API 키 입력 → `저장하고 연결` (해당 브라우저에만 저장)
   - 팀 배포: 아래 GitHub Pages 배포 시 Secret `GOOGLE_MAPS_API_KEY`로 주입. `config.js`에 직접 적어 커밋하지 마세요.
5. (선택) 운영용 지도 ID: 콘솔 **지도 관리**에서 JavaScript용 Map ID를 만들어 `config.js`의 `mapId`에 넣습니다. 비워 두면 Google 테스트용 `DEMO_MAP_ID`를 씁니다.

키가 틀리거나 API가 꺼져 있으면 앱이 데모 모드로 바뀌고 화면에 원인을 표시합니다.

### 보안

브라우저에서 Google 지도를 부르는 키는 구조상 페이지 요청 주소에 실려 보입니다. 숨길 수 없으므로 **키가 노출돼도 다른 곳에서 못 쓰게 제한하는 것**이 핵심입니다.

| 항목 | 설정 |
| --- | --- |
| 애플리케이션 제한 | 웹사이트(HTTP 리퍼러): `http://localhost:5173/*`, 배포 시 `https://<계정>.github.io/*` |
| API 제한 | Maps JavaScript API, Places API (New), Routes API 3개만 |
| 할당량 | API별 일일 요청 한도를 낮게 시작(콘솔 → 할당량) |
| 예산 알림 | 결제 → 예산 및 알림에서 월 예산·알림 메일 설정 |

앱이 하는 보호 조치

- 키는 해당 브라우저에만 저장합니다. '이 기기에 기억하기'를 끄면 sessionStorage에만 두어 탭을 닫을 때 지워집니다.
- 설정 화면에는 `AIza••••abcd`처럼 가려서 보여 주고, 키 삭제 버튼을 제공합니다.
- 키는 Google 지도 요청에만 쓰고, 일정 내보내기 파일에는 넣지 않습니다.
- 공유받은 일정 파일은 외부 입력으로 보고 모든 값을 형식·허용 목록으로 다시 정리합니다(`javascript:` 링크, HTML 삽입 차단).
- `npm test`가 저장소에 키 형태의 문자열이 커밋되면 실패합니다(CI에서도 실행).

키를 채팅·메신저·스크린샷으로 공유하지 마세요. 노출이 의심되면 콘솔에서 키를 **다시 생성**하거나 삭제하면 기존 키는 바로 무효가 됩니다.

### 비용 관련 메모

- Places 요청은 요청한 필드에 따라 과금 등급(SKU)이 정해집니다. 이 앱은 추천 품질을 위해 평점·리뷰 수·가격대·영업시간·사진을 요청하므로 기본 등급보다 높은 SKU가 적용됩니다. 정확한 단가와 무료 사용량은 [Google Maps Platform 가격표](https://mapsplatform.google.com/pricing/)에서 확인하세요.
- 같은 위치·조건의 추천 결과는 세션 동안, 경로 결과는 브라우저에 캐시해 중복 호출을 줄입니다.
- 콘솔에서 API별 일일 할당량과 예산 알림을 설정해 두기를 권장합니다.

### 알려진 제한

- **일본 대중교통 경로**: Google 개발자 포럼에 Directions API의 일본 내 TRANSIT 요청이 `ZERO_RESULTS`를 반환했다는 보고가 있습니다([스레드](https://discuss.google.dev/t/directions-api-transit-mode-returns-zero-results/378267)). 이 앱이 쓰는 Routes API에서도 같은지는 실제 키로 확인하지 못했습니다. 경로를 받지 못한 구간은 직선거리 기반 추정치로 계산하고 `추정` 표시를 붙이며, `길찾기 ↗`로 Google 지도 앱에서 실제 경로를 확인할 수 있습니다.
- 추정 이동시간은 직선거리 × 1.3에 도보 4.5km/h, 택시 18km/h(+4분), 대중교통 22km/h(+역 이동·대기 12분)를 가정한 근사치입니다.
- 데모 모드의 장소는 체험용 샘플(좌표 근사치)이며 평점·영업시간이 없습니다.

## GitHub Pages로 휴대폰에서 쓰기

`.github/workflows/pages.yml`이 기본 브랜치에 푸시될 때 테스트를 돌리고 Pages에 배포합니다. 배포 주소는 `https://contentsfit0914.github.io/Travelplan/`입니다.

1. 저장소를 공개로 전환합니다(무료 플랜의 Pages는 공개 저장소만 지원). Settings → General → 맨 아래 Danger Zone → Change visibility
2. Settings → Pages → Build and deployment → Source를 `GitHub Actions`로 설정합니다.
3. Google Cloud 키의 웹사이트 제한에 `https://contentsfit0914.github.io/*`를 추가합니다.
4. 배포 주소를 휴대폰에서 열고 ⚙ 설정에서 키를 입력합니다. 키는 그 휴대폰 브라우저에만 저장됩니다.

선택: 팀원이 키 입력 없이 쓰게 하려면 Secrets에 `GOOGLE_MAPS_API_KEY`를 등록합니다. 이 경우 키가 공개 사이트의 `config.js`에 들어가므로 웹사이트·API 제한이 유일한 보호 수단입니다.
